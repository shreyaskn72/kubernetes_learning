ಕುಬರ್ನೆಟಿಸ್ ನೆಟ್‌ವರ್ಕಿಂಗ್ ಟ್ರಾಫಿಕ್ ಫ್ಲೋ (Kubernetes Networking Traffic Flow) ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಎಂಬುದನ್ನು ಕೆಳಗಿನ ರೇಖಾಚಿತ್ರ (Flow diagram) ಮತ್ತು ವಿವರಣೆ ಸರಳವಾಗಿ ತೋರಿಸುತ್ತದೆ. [1] 
ಬಾಹ್ಯ ಬಳಕೆದಾರರಿಂದ (External User) ಹಿಡಿದು ಕ್ಲಸ್ಟರ್ ಒಳಗಿನ ಕಂಟೈನರ್‌ಗಳವರೆಗಿನ ಸಂಪೂರ್ಣ ಟ್ರಾಫಿಕ್ ಹರಿವು ಇಲ್ಲಿದೆ:

[ ಬಾಹ್ಯ ಕ್ಲೈಂಟ್ / External Client ]
               │
               ▼ (HTTP / HTTPS ವಿನಂತಿ)
┌─────────────────────────────────────────────────────────┐
│ 1. INGRESS / GATEWAY (ಟ್ರಾಫಿಕ್ ನಿಯಂತ್ರಣ ಮತ್ತು ರೂಟಿಂಗ್)       │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼ (ಸರಿಯಾದ ಹಾದಿಗೆ ಮರುನಿರ್ದೇಶನ)
┌─────────────────────────────────────────────────────────┐
│ 2. SERVICE (ಸ್ಥಿರವಾದ IP ಮತ್ತು ಲೋಡ್ ಬ್ಯಾಲೆನ್ಸಿಂಗ್)            │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼ (Kube-Proxy ನಿಯಮಗಳ ಮೂಲಕ ಮೂಲ ಪಾಡ್‌ಗೆ)
┌─────────────────────────────────────────────────────────┐
│ 3. POD (ಕ್ಲಸ್ಟರ್‌ನ ಪ್ರತ್ಯೇಕ ನೆಟ್‌ವರ್ಕ್ ಘಟಕ)                   │
│   ┌─────────────────────────────────────────────────┐   │
│   │ 4. CONTAINER A  ◄───(Localhost)───► CONTAINER B │   │
│   └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘

## ಪ್ರತಿಯೊಂದು ಹಂತದ ವಿವರವಾದ ಫ್ಲೋ (Step-by-Step Flow)

   1. ಬಾಹ್ಯ ಸಂವಹನ (External-to-Service):
   * ಬಳಕೆದಾರರು ಬ್ರೌಸರ್‌ನಲ್ಲಿ URL (ಉದಾಹರಣೆಗೆ: ://example.com) ಟೈಪ್ ಮಾಡಿದಾಗ, ಆ ವಿನಂತಿಯು ಮೊದಲು Ingress Controller ಅನ್ನು ತಲುಪುತ್ತದೆ.
      * Ingress ನಿಯಮಗಳ ಪ್ರಕಾರ, ಆ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಕ್ಲಸ್ಟರ್ ಒಳಗಿನ ನಿರ್ದಿಷ್ಟ Service ಗೆ ಕಳುಹಿಸಲಾಗುತ್ತದೆ.
   2. ಸರ್ವಿಸ್ ಲೋಡ್ ಬ್ಯಾಲೆನ್ಸಿಂಗ್ (Service-to-Pod):
   * ಪಾಡ್‌ಗಳು ನಿರಂತರವಾಗಿ ಬದಲಾಗುತ್ತಿರುವುದರಿಂದ (Dynamic), ಅವುಗಳ IP ಸ್ಥಿರವಾಗಿರುವುದಿಲ್ಲ.
      * ಆದ್ದರಿಂದ, Service ಒಂದು ಸ್ಥಿರವಾದ IP ಅನ್ನು ಹೊಂದಿರುತ್ತದೆ. ಇದು ತನಗೆ ಬರುವ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಅದರ ಅಡಿಯಲ್ಲಿ ಚಲಿಸುತ್ತಿರುವ ಲಭ್ಯವಿರುವ ಯಾವುದಾದರೂ ಒಂದು Pod ಗೆ ಸಮಾನವಾಗಿ ಹಂಚುತ್ತದೆ (Load Balancing). [2, 3] 
   3. ಪಾಡ್ ಸಂಪರ್ಕ (Pod-to-Pod):
   * ಕ್ಲಸ್ಟರ್ ಒಳಗಿರುವ ಒಂದು ಪಾಡ್ ಮತ್ತೊಂದು ಪಾಡ್‌ನೊಂದಿಗೆ ನೇರವಾಗಿ ಸಂವಹನ ನಡೆಸಲು CNI (Container Network Interface) ಸಹಾಯ ಮಾಡುತ್ತದೆ.
      * ಈ ಹಂತದಲ್ಲಿ ಯಾವುದೇ NAT (Network Address Translation) ಇಲ್ಲದೆಯೇ ನೇರ IP ಮೂಲಕ ಸಂಪರ್ಕ ಸಾಧ್ಯವಾಗುತ್ತದೆ. [4] 
   4. ಕಂಟೈನರ್ ಸಂಪರ್ಕ (Container-to-Container):
   * ಒಂದೇ ಪಾಡ್‌ನ ಒಳಗಡೆ ಒಂದಕ್ಕಿಂತ ಹೆಚ್ಚು ಕಂಟೈನರ್‌ಗಳಿದ್ದರೆ (ಉದಾಹರಣೆಗೆ: ಮುಖ್ಯ ಆಪ್ ಮತ್ತು ಸೈಡ್‌ಕಾರ್ ಲಾಗರ್), ಅವು ಪರಸ್ಪರ localhost:[Port] ಬಳಸಿ ತಕ್ಷಣವೇ ಸಂಪರ್ಕ ಸಾಧಿಸುತ್ತವೆ.
