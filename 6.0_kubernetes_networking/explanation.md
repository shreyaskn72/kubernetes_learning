ಕುಬರ್ನೆಟಿಸ್ ನೆಟ್‌ವರ್ಕಿಂಗ್ (Kubernetes Networking) "IP-per-Pod" ಮಾದರಿಯನ್ನು ಬಳಸುತ್ತದೆ. ಇದರರ್ಥ ಕ್ಲಸ್ಟರ್‌ನಲ್ಲಿರುವ ಪ್ರತಿ ಪಾಡ್ (Pod) ತನ್ನದೇ ಆದ ವಿಶಿಷ್ಟ IP ವಿಳಾಸವನ್ನು ಪಡೆಯುತ್ತದೆ. ಇದರಿಂದಾಗಿ ಪಾಡ್‌ಗಳು ವರ್ಚುವಲ್ ಮೆಷಿನ್‌ಗಳಂತೆ ಕೆಲಸ ಮಾಡುತ್ತವೆ ಮತ್ತು ಕಂಟೈನರ್ ಪೋರ್ಟ್‌ಗಳನ್ನು ಹೋಸ್ಟ್ ಪೋರ್ಟ್‌ಗಳಿಗೆ ಮ್ಯಾಪ್ ಮಾಡುವ ಅಗತ್ಯವಿರುವುದಿಲ್ಲ.
ಇದರ ಪ್ರಮುಖ 4 ನೆಟ್‌ವರ್ಕಿಂಗ್ ಪರಿಕಲ್ಪನೆಗಳನ್ನು ಕೆಳಗೆ ಸರಳವಾಗಿ ವಿವರಿಸಲಾಗಿದೆ.
------------------------------
## 1. ಕುಬರ್ನೆಟಿಸ್ ನೆಟ್‌ವರ್ಕಿಂಗ್‌ನ 4 ಹಂತಗಳು
ಕ್ಲಸ್ಟರ್‌ನಲ್ಲಿ ಕಮ್ಯುನಿಕೇಶನ್ (ಸಂಪರ್ಕ) ಪ್ರಮುಖವಾಗಿ ನಾಲ್ಕು ಹಂತಗಳಲ್ಲಿ ನಡೆಯುತ್ತದೆ:

* ಕಂಟೈನರ್‌ನಿಂದ ಕಂಟೈನರ್‌ಗೆ (Container-to-Container): ಒಂದೇ ಪಾಡ್ (Pod) ಒಳಗಿರುವ ಕಂಟೈನರ್‌ಗಳು ಒಂದೇ ನೆಟ್‌ವರ್ಕ್ ಮತ್ತು IP ವಿಳಾಸವನ್ನು ಹಂಚಿಕೊಳ್ಳುತ್ತವೆ. ಇವು localhost ಮೂಲಕ ಪರಸ್ಪರ ಸಂವಹನ ನಡೆಸುತ್ತವೆ.
* ಪಾಡ್‌ನಿಂದ ಪಾಡ್‌ಗೆ (Pod-to-Pod): ಯಾವುದೇ ಎರಡು ಪಾಡ್‌ಗಳು ಕ್ಲಸ್ಟರ್‌ನ ಯಾವುದೇ ನೋಡ್‌ನಲ್ಲಿದ್ದರೂ, NAT ಇಲ್ಲದೆಯೇ ನೇರವಾಗಿ ತಮ್ಮ IP ವಿಳಾಸಗಳ ಮೂಲಕ ಸಂಪರ್ಕ ಸಾಧಿಸಬಹುದು.
* ಪಾಡ್‌ನಿಂದ ಸರ್ವಿಸ್‌ಗೆ (Pod-to-Service): ಪಾಡ್‌ಗಳ IP ವಿಳಾಸಗಳು ಶಾಶ್ವತವಲ್ಲ (Dynamic). ಆದ್ದರಿಂದ, ಪಾಡ್‌ಗಳಿಗೆ ಸ್ಥಿರವಾದ (Stable) ಒಂದು ವಿಳಾಸವನ್ನು ನೀಡಲು ಸರ್ವಿಸ್ (Service) ಅನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.
* ಹೊರಗಿನಿಂದ ಸರ್ವಿಸ್‌ಗೆ (External-to-Service): ಕ್ಲಸ್ಟರ್‌ನ ಹೊರಗಿರುವ ಬಳಕೆದಾರರು ಅಥವಾ ಗ್ರಾಹಕರು ಕ್ಲಸ್ಟರ್ ಒಳಗಿನ ಅಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನು ಸಂಪರ್ಕಿಸಲು ಈ ಹಂತವನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.

------------------------------
## 2. ಪ್ರಮುಖ ನೆಟ್‌ವರ್ಕಿಂಗ್ ಘಟಕಗಳು (Components)

* CNI (Container Network Interface): ಕುಬರ್ನೆಟಿಸ್ ಸ್ವತಃ ನೆಟ್‌ವರ್ಕಿಂಗ್ ವ್ಯವಸ್ಥೆಯನ್ನು ಹೊಂದಿರುವುದಿಲ್ಲ. ಇದು ಪಾಡ್‌ಗಳಿಗೆ IP ವಿಳಾಸ ನೀಡಲು ಮತ್ತು ನೆಟ್‌ವರ್ಕ್ ನಿರ್ವಹಿಸಲು Calico, Cilium ಅಥವಾ Flannel ನಂತಹ ಮೂರನೇ ವ್ಯಕ್ತಿಯ CNI ಪ್ಲಗಿನ್‌ಗಳನ್ನು ಬಳಸುತ್ತದೆ.
* kube-proxy: ಇದು ಪ್ರತಿ ನೋಡ್‌ನಲ್ಲಿ ಚಲಿಸುವ ನೆಟ್‌ವರ್ಕ್ ಡೀಮನ್ (Daemon). ಇದು ಸರ್ವಿಸ್‌ಗಳಿಗೆ ಬರುವ ಟ್ರಾಫಿಕ್ ಅನ್ನು ಸರಿಯಾದ ಪಾಡ್‌ಗೆ ಮರುನಿರ್ದೇಶಿಸಲು (Route) ಸಿಸ್ಟಮ್ ರೂಲ್ಸ್ ಬರೆಯುತ್ತದೆ.
* CoreDNS: ಇದು ಕ್ಲಸ್ಟರ್‌ನ ಒಳಗಿನ DNS ವ್ಯವಸ್ಥೆ. ಇದು ಸರ್ವಿಸ್ ಹೆಸರುಗಳನ್ನು ಅವುಗಳ IP ವಿಳಾಸಗಳಿಗೆ ಮ್ಯಾಪ್ ಮಾಡುತ್ತದೆ. ಇದರಿಂದ ಅಪ್ಲಿಕೇಶನ್‌ಗಳು IP ಬದಲಾಗಿ ಸರ್ವಿಸ್ ಹೆಸರನ್ನು ಬಳಸಿ ಕಮ್ಯುನಿಕೇಟ್ ಮಾಡಬಹುದು.

------------------------------
## 3. ಅಪ್ಲಿಕೇಶನ್ ಹೊರಗಿನ ಪ್ರಪಂಚಕ್ಕೆ ಮುಕ್ತಗೊಳಿಸುವುದು (Service Types)
ಕ್ಲಸ್ಟರ್‌ನ ಹೊರಗಿನಿಂದ ಬರುವ ಟ್ರಾಫಿಕ್ ಅನ್ನು ನಿಯಂತ್ರಿಸಲು ನಾಲ್ಕು ಮುಖ್ಯ ಸರ್ವಿಸ್ ಪ್ರಕಾರಗಳಿವೆ:

| ಸರ್ವಿಸ್ ಪ್ರಕಾರ (Service Type) | ಲಭ್ಯತೆ (Scope) | ಪ್ರಮುಖ ಬಳಕೆ (Use Case) |
|---|---|---|
| ClusterIP | ಕ್ಲಸ್ಟರ್ ಒಳಗಡೆ ಮಾತ್ರ. | ಡೇಟಾಬೇಸ್ ಅಥವಾ ಆಂತರಿಕ ಮೈಕ್ರೋಸರ್ವಿಸ್‌ಗಳಿಗಾಗಿ ಬಳಕೆ. |
| NodePort | ಸ್ಟ್ಯಾಟಿಕ್ ಪೋರ್ಟ್ ಮೂಲಕ ಹೊರಗಡೆ ಲಭ್ಯ. | ಟೆಸ್ಟಿಂಗ್ ಅಥವಾ ಲೋಕಲ್ ನೆಟ್‌ವರ್ಕ್ ಸಂಪರ್ಕಕ್ಕಾಗಿ ಬಳಕೆ. |
| LoadBalancer | ಕ್ಲೌಡ್ ಪ್ರೊವೈಡರ್ ಮೂಲಕ ಹೊರಗಡೆ ಲಭ್ಯ. | ಪ್ರೊಡಕ್ಷನ್ ಪರಿಸರದಲ್ಲಿ ಹೊರಗಿನ ಟ್ರಾಫಿಕ್ ಅನ್ನು ನೇರವಾಗಿ ಆಪ್‌ಗೆ ಕಳುಹಿಸಲು ಬಳಕೆ. |
| ExternalName | CoreDNS ಮೂಲಕ ರೀಡೈರೆಕ್ಟ್. | ಕ್ಲಸ್ಟರ್ ಒಳಗಿನ ಕರೆಯನ್ನು ಹೊರಗಿನ ಡೊಮೇನ್ ಹೆಸರಿಗೆ ಮ್ಯಾಪ್ ಮಾಡಲು ಬಳಕೆ. |

## 4. ಸುಧಾರಿತ ನೆಟ್‌ವರ್ಕಿಂಗ್ ಮತ್ತು ಭದ್ರತೆ

* Ingress & Gateway API: ಪ್ರತಿ ಸರ್ವಿಸ್‌ಗೆ ಪ್ರತ್ಯೇಕ ಲೋಡ್ ಬ್ಯಾಲೆನ್ಸರ್ ಬಳಸುವುದು ದುಬಾರಿಯಾಗುತ್ತದೆ. Ingress ಒಂದೇ IP ಮೂಲಕ HTTP/HTTPS ಟ್ರಾಫಿಕ್ ಅನ್ನು ಅವುಗಳ ಪಾತ್ (Path/URL) ಆಧರಿಸಿ ಬೇರೆ ಬೇರೆ ಸರ್ವಿಸ್‌ಗಳಿಗೆ ಕಳುಹಿಸಲು ಸಹಾಯ ಮಾಡುತ್ತದೆ.
* Network Policies: ಪೂರ್ವನಿಯೋಜಿತವಾಗಿ (Default) ಎಲ್ಲಾ ಪಾಡ್‌ಗಳು ಪರಸ್ಪರ ಮುಕ್ತವಾಗಿ ಸಂವಹನ ನಡೆಸಬಹುದು. Network Policies ಕ್ಲಸ್ಟರ್‌ನ ಫೈರ್‌ವಾಲ್ (Firewall) ನಂತೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಇದು ಯಾವ ಪಾಡ್ ಯಾವ ಪಾಡ್‌ನೊಂದಿಗೆ ಸಂವಹನ ನಡೆಸಬೇಕು ಎಂಬುದನ್ನು ನಿಯಂತ್ರಿಸುತ್ತದೆ.
